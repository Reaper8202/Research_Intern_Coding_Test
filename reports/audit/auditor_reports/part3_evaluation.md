## 2. Findings worth fixing

Ranked. "Blocker (before sending)" means the submission would not meet the brief as it stands; nothing found breaks the metric or the CV protocol.

1. **Blocker (before sending) — the wandb project behind the report's only curve link is not publicly readable** (C9). `docs/report.md:20` gives the project URL; the anonymous public API returns `project: null` for it while a public control project returns data. The brief requires a wandb link the organisers can open. Fix: make the project public (or the 15 member runs and the two `val-bundle-*` groups), then list the member run names (`small-v2-c1[-seedN]-fold<k>-F`) or their IDs from `reports/final/manifest.json` in section 2 of the report so a reader can find the submitted members without the manifest.

2. **Should-fix — rule S of round 3 was committed while its evidence was being computed** (C4). `configs/budget_v3.toml` was committed at 21:18:44; `reports/stacking/clean/stacking.json` was written at 21:19:52; the stacking run needs at least ~12 minutes on this machine (nine paired BCa calls, each >= 82 s from the jackknife alone; `time_bootstrap.py`) and logs every stacker's pooled score before the bootstraps start (`stacking.py:173-178`). D38's sentence "written ... before any of the numbers below existed" and the file header "Written ... at 21:40" cannot both be right. Fix: state the real sequence in D38 and in the budget header (what was running, what had been printed, when the rule was written), or label rule S as written with the stacker point estimates in view and let the paired intervals and val attempt 2 carry the claim.

3. **Should-fix — five descriptive counts in the report do not match the committed files** (C10, C6). "Nine targets below 0.6 for every model" (7 of the 9 for the three main models, 5 for all six); "seven targets above 0.95 for every model" (obesity 0.947 for LightGBM counts); "nine targets have at most eight positives" (11); "193 unit tests" (180 functions / 195 items); "24 transformer trials" (28 configurations trained, 25 five-fold plus 3 screens). Fix: regenerate these sentences from `reports/val/val_per_target.csv`, `pytest --collect-only`, and `models/transformer/*/fold*/F/run.json`, and say which models "every model" means.

4. **Should-fix — the round-3 stacking intervals used 200 bootstrap resamples, not the 1,000 the report states** (C2, C10). `reports/stacking/clean/stacking.json` and `with_clock_codes/stacking.json` record `"n_boot": 200` in all nine comparisons; `docs/report.md:193` says 1,000 and the quoted intervals (`docs/report.md:172-174`, `docs/model_results.md:56-58`, D38) carry no resample count. Fix: rerun `make stacking` with the default 1,000 (about 15 minutes; the point estimates will not change) or state "200 resamples" wherever those intervals appear.

5. **Should-fix — the strong baseline's grid was exhausted at its minimum on all three axes and not extended** (C3). Both LightGBM runs selected `num_leaves 4, min_child_samples 20, n_estimators 100` with `grid_edge` on all three (`reports/lightgbm*/cv_summary.json`), with learning rate and sampling fixed (`lightgbm_cv.py:67-78`). The blend's two LightGBM members use this edge setting. Fix: extend the grid toward simpler models (num_leaves 2-3, n_estimators 25-50, learning rate 0.02, min_child_samples 10) on the same folds, and if the budget allows average a few LightGBM seeds so the comparison with the 15-model transformer ensemble is like for like.

6. **Should-fix — val comparison rows have no interval of their own, and the report's tally of val uses omits the step-2 scoring** (C5). `val_score.py:397-399` bootstraps only the final model; LightGBM, logistic regression and incidence val rows in `docs/report.md:295-299`, `README.md:196-199` and the model card carry no interval. The step-2 baselines were scored on val on 29 Oct (`reports/baseline/metrics.json`), recorded in README/D37 but not in `docs/report.md:40-41,196-199` ("two recorded val runs"). Fix: add single-model BCa intervals for the comparison rows (one extra `bootstrap_comparison` call each in `score_bundle`; the attempt-2 bundle can be re-read from its saved prediction files without a new val run) or state that only paired intervals are given; count the step-2 val scoring in the report.

7. **Should-fix — the selection-optimism estimate is not a number with a source** (C4). The only figure is "about 0.003" for epoch selection (`docs/decisions.md:388`), which no committed file supports; the configuration search has no estimate. Fix: report the val-minus-CV gap of the chosen blend as the empirical optimism (mean fold 0.780 and pooled 0.774 in CV against 0.767 on val) and derive the epoch effect from the committed curves (`reports/val/val_curves.csv`: selected epochs vs val-best epochs, +0.008) or from best-vs-last-epoch held-out scores.

8. **Nit — the round-2 component test is disclosed only in `docs/decisions.md`** (C4). It was written after A3 and X1 had finished and is more lenient than rule 5.3 (both components failed the rule alone). One sentence in `docs/report.md` section 2 ("Tuning, pre-registered") would make the report self-contained.

9. **Nit — state "no stratification" explicitly** (C1). `docs/model_plan.md` 5.1 names the `KFold` call; add the word and the minimum positives per fold (5, 4, 4, 6, 6) to the report's evaluation-protocol paragraph.

## 4. Scripts and outputs in this directory

* `recompute_val.py` / `recompute_val.out`: scikit-learn recomputation of every val file, masked and at-risk; prior-cell convention effect; percentile and BCa bootstraps; subgroups; per-target checks.
* `recompute_oof.py` / `recompute_oof.out`: pooled and mean-fold OOF metrics of the three stackers and three bases; logit-mean identity; nested logistic refit; rule S; Platt fold table; ECE; oracle.
* `check_rules.py` / `check_rules.out`: rounds 1-3 adoption rules recomputed from `run.json` records; seed spreads; S/H/F.
* `time_bootstrap.py`: timing of one paired BCa call (82 s at n_boot=20).
